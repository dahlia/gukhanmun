辭典 形式
=========

이 文書는 `gukhanmun-mkdict`가 消費하는 正規化된 辭典 入力 形式과, 그 入力에서
產出되는 FST/CDB 辭典 파일 配置를 明細합니다.  이는 辭典 抽出器, 使用者가
維持하는 用語集, 백엔드 빌더 사이의 境界입니다.


正準 TSV 入力
-------------

主 入力 形式은 必須 헤더 行을 가진 UTF-8 TSV입니다.  各 파일은 적어도 다음 列을
包含해야 합니다:

| 列       | 必須 | 意味                             |
| -------- | ---- | -------------------------------- |
| `hanja`  | 예   | 찾기 키로 使用되는 出處 表記.    |
| `hangul` | 예   | 그 키에 對해 내보내는 한글 讀音. |

다음 選擇的 列이 認識됩니다:

| 列               | 基本    | 意味                                         |
| ---------------- | ------- | -------------------------------------------- |
| `require_hanja`  | `false` | 렌더러가 出處 漢字를 보이게 維持하도록 強制. |
| `require_hangul` | `false` | 렌더러가 한글 倂記를 包含하도록 強制.        |

참거짓 값은 `true`, `false`, `1`, `0`입니다.  비어 있는 選擇的 참거짓 셀은
`false`로 다뤄집니다.

`category`, `source`, `note` 같은 追加 列은 將來 擴張 餘地로 許容됩니다.  現在의
빌더는 그것들을 消費하지 않으며; 짧은 警告를 내고 그 값을 無視합니다.

例示:

~~~~ tsv
hanja	hangul	require_hanja	require_hangul	category
天地	천지	false	false	basic
漢字	한자	true	false	basic
色깔論	색깔론	false	true	mixed
~~~~


CSV와 JSONL 入力
----------------

`gukhanmun-mkdict`는 各 파일 擴張子로부터 入力 파서를 고릅니다.  *.tsv*는 正準
TSV 파서를, *.csv*는 CSV 파서를, *.jsonl*은 JSON Lines 파서를 使用하며, 알 수
없는 擴張子는 互換性을 爲해 TSV로 다뤄집니다.

CSV 파일은 TSV와 같은 헤더 이름을 使用합니다:

~~~~ csv
hanja,hangul,require_hanja,require_hangul
天地,천지,true,false
~~~~

各 JSONL 줄은 하나의 客體입니다.  참거짓 필드는 snake\_case나 camelCase 表記를
모두 받습니다:

~~~~ json
{"hanja":"漢字","hangul":"한자","requireHanja":false,"requireHangul":true}
~~~~


倂合 政策
---------

여러 入力 파일이 提供되거나 한 入力 파일이 `hanja` 키를 反復할 때,
`gukhanmun-mkdict`는 設定된 倂合 政策을 適用합니다:

 -  `error`: 첫 重複 키에서 失敗합니다.  이것이 基本입니다.
 -  `first-wins`: 첫 項目을 維持하고 以後 重複을 無視합니다.
 -  `last-wins`: 앞선 項目을 마지막 重複으로 置換합니다.

倂合 後, 項目은 백엔드 인코딩 前에 UTF-8 키 바이트 順으로 整列됩니다.  이로써
같은 正規化 入力과 메타데이터에 對해 生成되는 FST와 CDB 產出物이 決定的이
됩니다.


빌드 메타데이터
---------------

生成되는 모든 백엔드 파일은 CBOR 메타데이터를 內藏합니다.  最小 키는 다음과
같습니다:

| 키               | 出處                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| `source`         | `--metadata source=...`, 또는 빈 文字列.                                       |
| `license`        | `--metadata license=...`, 또는 빈 文字列.                                      |
| `build_date`     | `--metadata build_date=...`, `SOURCE_DATE_EPOCH`, 또는 `1970-01-01T00:00:00Z`. |
| `entry_count`    | 倂合된 辭典 項目 數.                                                           |
| `version`        | 辭典 파일 形式 版本.                                                           |
| `max_word_chars` | 유니코드 스칼라 값 單位의 最大 키 길이.                                        |
| `max_key_bytes`  | UTF-8 바이트 單位의 最大 키 길이.                                              |
| `prefix_count`   | CDB 專用: 接頭 레코드 數.                                                      |

`entry_count`, `version`, `max_word_chars`, `max_key_bytes`, `prefix_count`은
豫約되어 있으며 `--metadata`로 提供할 수 없습니다.  다른 `--metadata KEY=VAL`
雙은 文字列 값으로 保存됩니다.

再現 可能한 빌드를 爲해, 빌더는 基本的으로 現在 時刻을 使用하지 않습니다.
`build_date`가 明示的으로 넘어오지 않고 `SOURCE_DATE_EPOCH`가 設定되어 있으면,
그 에포크가 UTC RFC 3339로 形式化됩니다.  두 값 모두 없으면 固定 날짜
`1970-01-01T00:00:00Z`가 使用됩니다.


FST 백엔드 파일
---------------

처음 具顯된 백엔드 形式은 `fst`입니다.  파일은 다음을 담습니다:

1.  固定된 64바이트 리틀 엔디언 헤더.
2.  CBOR 메타데이터 맵.
3.  `fst::Map` 바이트.
4.  連續된 讀音/페이로드 테이블.

固定 헤더 필드는 다음과 같습니다:

| 필드            | 크기 | 意味                                  |
| --------------- | ---- | ------------------------------------- |
| magic           | 8    | `GUKHMFST`.                           |
| version         | 4    | 파일 形式 版本, `1`부터 `4`.          |
| header length   | 4    | 固定 헤더 길이, 現在 `64`.            |
| metadata offset | 8    | CBOR 메타데이터의 바이트 오프셋.      |
| metadata length | 8    | CBOR 메타데이터의 바이트 길이.        |
| FST offset      | 8    | `fst::Map` 바이트의 바이트 오프셋.    |
| FST length      | 8    | `fst::Map` 바이트의 바이트 길이.      |
| readings offset | 8    | 讀音/페이로드 테이블의 바이트 오프셋. |
| readings length | 8    | 讀音/페이로드 테이블의 바이트 길이.   |

各 FST 키는 `hanja` 列의 UTF-8 바이트입니다.  各 FST 값은 64비트 整數입니다:

| 비트  | 필드                                                                |
| ----- | ------------------------------------------------------------------- |
| 0-15  | UTF-8 바이트 單位의 讀音 길이.                                      |
| 16-23 | 標識 비트필드: 비트 0은 `require_hanja`, 비트 1은 `require_hangul`. |
| 24-63 | 讀音 文字列 테이블 안의 오프셋.                                     |

讀音 바이트는 FST 값이 아니라 讀音 文字列 테이블에 貯藏되는데, 이는 FST 값이
固定 幅 整數이기 때문입니다.

런타임에 `gukhanmun-fst`는 固定 헤더와 CBOR 메타데이터를 卽時 디코딩합니다.
그러면 FST 맵 바이트와 連續된 讀音 테이블은 하나의 바이트 背後 貯藏所를
共有합니다: `FstDictionary::open()`과 `FstDictionary::from_bytes()`에는 所有된
힙 바이트, `FstDictionary::from_static_bytes()`에는 靜的 바이트입니다.  이
크레이트는 安全한 파일 基盤 mmap 로더(loader)를 일부러 露出하지 않는데, 이는
辭典이 살아 있는 동안 다른 파일 記述子나 프로세스가 寫像된 파일을 不變으로
維持할 것임을 Rust가 強制할 수 없기 때문입니다.  `entries()`와
`has_homophone()`은 FST를 列擧하므로 全體 辭典 스캔으로 남습니다; 反復되는
同音異義 檢査가 必要한 呼出者는 코어의 同音異義 미들웨어의 一括 인덱스를
使用해야 합니다.


CDB 백엔드 파일
---------------

CDB 백엔드 形式은 `cdb`입니다.  이는 CDB 키 空間에 內藏된 트라이(trie)를
使用합니다: 各 辭典 키의 各 接頭辭가 CDB 키로 쓰입니다.  完全한 辭典 項目인
接頭 레코드는 讀音과 標識 비트를 싣고; 더 긴 項目으로 이어지기만 하는 接頭
레코드는 讀音을 싣지 않습니다.

| 오프셋 | 크기          | 필드                                                                |
| ------ | ------------- | ------------------------------------------------------------------- |
| 0      | 1             | `is_complete` (이 接頭辭 自體가 項目이면 `1`).                      |
| 1      | 1             | 標識 비트필드: 비트 0은 `require_hanja`, 비트 1은 `require_hangul`. |
| 2      | 2             | UTF-8 바이트 單位의 讀音 길이, 리틀 엔디언; 非完全이면 `0`.         |
| 4      | `reading_len` | 讀音 바이트.                                                        |

메타데이터 CBOR 맵은 豫約 키 `__gukhanmun_meta__` 아래에 貯藏됩니다.

런타임 CDB 백엔드는 `cdb` 크레이트의 파일 基盤 리더(reader)를 使用하고 백엔드를
`HanjaDictionary` 뒤에 不透明하게 維持합니다.  이는 安全하지 않은 mmap 表面을
더하지 않고도 全體 CDB 파일을 Gukhanmun 所有 버퍼로 불러오는 것을 이미 避합니다.


檢證
----

`--validate`를 쓰면 `gukhanmun-mkdict`는 出力을 쓴 뒤 選擇된 백엔드로 다시 열어,
倂合된 모든 項目이 相對 選好度·接尾 讀音·標識를 包含한 같은 候補 集合으로
復元될 수 있는지 檢査합니다.  項目 數는 候補가 아니라 키 單位로 比較합니다.
檢證 失敗는 致命的입니다.


複數 讀音과 v2
--------------

TSV/CSV의 `preference`와 `suffix_reading` 列로 여러 讀音과 候補別 接尾 讀音을
記錄한다. `preference`가 빈칸이 아니면(`0`도 包含) 같은 파일의 그 키 行들을
하나의 候補 集合으로 다룬다. 같은 키에 빈칸과 數値를 섞으면 誤謬이다.
JSONL도 `preference`와 `suffixReading`/`suffix_reading`을 받는다.
`source_ids` 列만으로는 바이너리에 들어가지 않는다. 컴파일된 出處 根據는
別途의 `--evidence` 入力으로 傳達한다.

큰 選好度가 優先하고, 同率이면 讀音·接尾 讀音 바이트 順으로 고른다. 같은 쌍의
標識만 OR로 合치고 最小 選好度를 빼서 正規化한다. 파일 사이의
`first-wins`/`last-wins`/`error`는 키의 集合 全體에 適用한다.
`reading` 規則은 該當 候補에만 適用한다.

單一 候補이며 接尾 讀音이 없으면 旣存 v1을 輸出하고, 그 밖에는 v2를 쓴다.
새 리더는 두 版本을 모두 支援하지만 舊版은 v2를 拒否하므로, 使用하는
크레이트·바인딩도 함께 更新해야 한다. v2의 `0x80` 標識 바이트는 候補 페이로드를
가리킨다. FST는 旣存 16비트 길이와 40비트 오프셋을 使用한다. CDB는 오프셋
2의 16비트 길이가 페이로드 길이가 되고 페이로드는 오프셋 4에서 始作한다.

페이로드는 리틀 엔디언 `u16` 候補 數와, 各 候補의 `u32` 選好度, `u8` 標識,
`u16` 讀音 바이트 길이, `u16` 接尾 바이트 길이, UTF-8 讀音·接尾 바이트로
構成된다. 接尾 길이 0은 없음이다. 全體 길이는 65,535 바이트 以下이며 빈 集合·빈
讀音, 不明 標識, 잘린 값, 뒤에 남는 바이트, 重複 쌍, 非正準 順序·選好度와 v1의
페이로드 標識는 拒否한다. `--validate`는 키 數와 全體 候補 集合을 檢證한다.

`lookup().candidates()`와 `candidate_matches_at()`/`candidate_entries()`는
全體 候補를, 旣存 `reading()`/`mark()`/`matches_at()`/`entries()`는 基本값을
提供한다. 單一 候補·接尾 없음은 스칼라 配置를 써야 한다. 詳細 配置는
[英語 明細](../../en/internals/dictionary-format.md#version-2-candidate-payloads)도
參考한다.


버전 4의 必須 出處 根據
-----------------------

`--evidence source-evidence.json`을 指定하면 스칼라 單一 候補도 버전 4
컨테이너로 만든다. 根據가 없으면 스칼라는 버전 1, 候補 集合은 버전 2,
別名은 버전 3을 維持한다. 새 리더는 1–4를 支援하며, 옛 리더는 버전 4를
拒否한다. JSON 根據의 `schema_version`은 컨테이너와 別途이며 現在 `1`이다.

CBOR 메타데이터의 豫約 키 `candidate_evidence`는 文字列이 아닌 다음 튜플이다:

~~~~ text
[schema_version, role, {
  key: [[reading, suffix_or_null,
         [[word_id, sense_id_or_null, origin], ...],
         authorized_forms, diagnostics], ...], ...
}]
~~~~

初聲形/位置形 쌍으로 正準 候補와 連結하고, 各 寄與 記錄의 單語/語義 ID와
原語 分類, 許容 形式·타입이 指定된 關係·診斷을 保存한다. 單語 ID와 語義 ID는
같은 數値라도 別個이며, 符號 없는 64비트 精度를 維持해야 한다. 數値
優先度·標識· 別名은 旣存 候補 페이로드를 그대로 使用한다.

리더는 튜플 構造·스키마·役割·重複·候補 連結을 檢證한 뒤 根據를 公開한다.
버전 4에 두 必須 根據 項目이 모두 없는 境遇, 옛 컨테이너에 根據가 存在하는
境遇, 未支援 스키마, 重複된 必須 메타데이터나 오래된 候補 連結은 모두 誤謬이다.
一部 候補의 根據만 記錄할 수 있으며, 記錄하지 않은 候補의 根據는 未知이다.
`HanjaDictionary::source_evidence()`로 타입이 指定된 根據를 確認하며, 文字列
메타데이터 API에는 이 項目을 넣지 않는다.

《標準國語大辭典》 抽出器의 `--evidence-output`과 外來語 更新 태스크가
再現 可能한 JSON 根據를 만든다. 更新 道具는 JavaScript의 安全한 整數 範圍를
넘는 ID도 正確한 數値 토큰으로 比較한다.


必須 句 根據
------------

`--phrase-evidence phrase-evidence.json`은 CBOR 메타데이터에 別途 타입이 指定된
`phrase_evidence`를 넣는다. `PhraseEvidence`의 `schema_version`과
`policy_version`은 現在 모두 `1`이다. 旣存 `DictionaryEvidence`와
`candidate_evidence`의 스키마는 버전 1을 維持하며, 句 規則이 候補 許容
튜플을 擴張하지 않는다. 두 項目은 모두 必須 메타데이터이며 文字列 API에서
除外한다. Rust는 `HanjaDictionary::phrase_evidence()`로 句 規則을 確認한다.

어느 根據 項目이든 있으면 컨테이너는 버전 4이다. 버전 4는 둘 中 하나 以上을
要求하고 兩쪽을 함께 許容하며, 버전 1–3은 둘 다 담을 수 없다. 句 根據가 있는
파일을 읽으려면 消費하는 런타임도 句 擴張을 支援해야 한다. 辭典을 다시 빌드할
때 런타임도 함께 更新한다. 런타임은 辭典 파일 하나만 불러오며 이름으로 다른
파일을 찾거나 네트워크에서 補充하거나 別途 根據 파일을 要求하지 않는다.

規則은 原本 單語 ID와 順序 있는 조각을 保存한다. 各 조각은 完全한 原本 讀音과
正確한 表記를 담고, 表記는 候補의 原本 語頭/接尾 讀音 쌍에 連結된다.
런타임 制約은 出處 基準 候補와 함께 같은 完全한 出力 쌍도 要求한다. 追加
兄弟 表記에는 明示的 原本 根據가 必要하다. 리터럴 專用 조각은 辭典 連結이
없어도 된다. 마지막 조각의 擴張은 推定한 文法的 接尾辭가 아니라 完全한 子
項目 表記와 타입이 指定된 父母 單語→子 單語 關係를 담는다. 빌더는 別名과 規則
適用 後의 最終 正規化 候補에 連結을 檢證한다.

《標準國語大辭典》 抽出器는 `--phrase-evidence-output`과
`--phrase-manifest-output`으로 빌드 入力과 採擇 明細를 쓴다. 두 옵션은 함께
指定하며, 再現 可能한 빌드 產出物이다. 監査用 *phrase-manifest.json*은 貯藏所에
남기며 配布하는 `gukhanmun-stdict` 크레이트에서는 除外한다. 런타임의
*phrase-evidence.json*은 包含한다. 句 制約은 單語 候補 行과 別途로
컴파일한다. 句를 찾기 키로 넣거나
構成 單語의 讀音을 固定하지 않는다. 런타임은 參與 조각 全體가 確定된 經路와
所有 出處의 適格 候補에 整列된 뒤에만 制約을 適用한다. `^`는 `U+0020`을 0個나
1個 許容하며, 한글 對案은 完全한 조각으로 一致해야 한다. 글字마다 任意로
漢字와 한글을 섞을 수는 없다.

리더는 未支援 스키마/政策, 重複된 必須 項目, 잘못된 關係 記錄과 오래된 候補
連結, 호스트 限度를 넘는 根據를 拒否한다. 디코딩 前에 메타데이터 바이트 限度를
檢査하고, 公開 前에 規則·조각·對案·길이 限度를 確認한다. 런타임 探索/一致
限度에 닿으면 任意의 一部 制約만 採擇하지 않고 影響을 받는 有限한 區間에서
根據를 保留한다. 衝突과 限度에서는 從來의 助詞 考慮 讀音을 維持하며,
`ResolutionReport`로 確認할 수 있다.

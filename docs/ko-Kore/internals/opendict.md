《우리말샘》
============

`gukhanmun-opendict`는 國立國語院 《우리말샘》 JSON 全體 내려받기에서 만든
分類別 辭典 스냅숏을 內藏합니다.

原本 덤프는 이 貯藏所에 커밋하지 않습니다. 代身
*crates/gukhanmun-opendict/data/* 아래의 네 TSV 파일을 커밋된 正本으로 둡니다.
네 파일은 原本의 `senseinfo.type` 값인 一般語, 北韓語, 方言, 옛말로 나뉩니다.


스냅숏
------

현재 《우리말샘》 데이터는 *crates/gukhanmun-opendict/data/* 디렉터리의 TSV
파일에 保存됩니다. 같은 디렉터리의 *metadata.json*은 生成된 바이너리에 들어가는
出處 識別子, 덤프 날짜, 라이선스를 記錄합니다. 週刊 更新 작업으로 收集한
스냅숏에는 壓縮 파일의 체크섬, 原本 項目 數, 出力 파일별 해시를 담은
*source.json*도 있습니다. 出處 表示는 *NOTICE.md*를 參考하세요.

2026年 6月 3日 스냅숏의 候補 移行은 以前 키 集合, 選擇한 讀音과
註釋 標識를 保存했습니다. 相容性 決定은 *defaults.tsv*에 남아 있으며,
更新 작업은 이 決定을 自動으로 바꾸지 않습니다. 候補 集合이 바뀌면
管理者의 檢討가 必要합니다.


再生成
------

壓縮 파일이나 壓縮을 푼 디렉터리를 놓고 다음 命令을 實行합니다:

~~~~ sh
mise run opendict-extract -- /path/to/opendict.zip
mise run opendict-extract-check -- /path/to/opendict.zip
~~~~

抽出器는 單一 JSON 파일, 公式 壓縮 파일, JSON 디렉터리를 모두
받습니다. 디렉터리 內 項目과 壓縮 파일 內 項目은 文字列 順序로 處理합니다. 各
分類 TSV는 UTF-8이고 辭典 키 順으로 決定的으로 整列됩니다.


抽出 方針
---------

`word_unit`이 `어휘`인 項目 中 `original_language_info`에서 漢字가 있는
檢索 키를 만들 수 있는 것만 包含합니다. 讀音은 `wordinfo.word`에서
오며, 同形異義語 番號, 하이픈, `^` 區分子는 제거합니다.

키 生成은 `gukhanmun-stdict`와 共有하는 로직을 씁니다. 漢字 分節은
그대로 키가 되고, 固有語 分節은 漢字 周邊에 남을 수 있습니다.
`Beijing[北京]` 같은 괄호 속 外來 漢字 表記는 保存하지만, 漢字가 없는
外來語 分節은 건너뜁니다. 單一 漢字 外來語 讀音은 Unihan 對替의
韓國 漢字音 讀音을 가리지 않도록 건너뜁니다.

各 分類에서 서로 다른 讀音을 모두 保存합니다. 같은 (讀音, 接尾 讀音)은
하나의 候補로 합치고, 寄與한 모든 `target_code` 뜻풀이 識別子를
`source_ids`에 數値順으로 重複 없이 保存합니다. 識別子는 TSV에만 남고
實行 時 바이너리에는 넣지 않습니다. TSV의 일곱 欄은 `hanja`, `hangul`,
`require_hanja`, `require_hangul`, `preference`, `suffix_reading`,
`source_ids`이며, 두 註釋 標識는 모두 false입니다. `entries_written`은
候補 行 數이고 `duplicate_keys`는 같은 키가 다시 나타난 回數입니다.

*data/defaults.tsv*는 分類와 키를 함께 識別子로 쓰며, 選擇한 讀音과
接尾 讀音, 전체 候補의 整列된 JSON 서명, 選擇 理由를 記錄합니다.
文字列 順序가 以前의 기본값과 다를 때만 決定을 固定합니다. 候補 集合이
바뀌거나 選擇한 候補가 없으면 디렉터리/ZIP 抽出에 失敗합니다. 單一 JSON
파일과 `extract_json_reader_to_files`는 알려진 候補의 一部나 接尾 讀音의
對應 記錄이 빠진 入力도 許容하며, 전체 集合이 모일 때까지 文字列 順序로
選擇합니다. 새로운 候補는 여전히 檢證에 失敗합니다. 없거나 不完全한
固定 決定은 `skipped_default_pins`에 셉니다. 固定하지 않은 競合은 core 選擇器의
讀音/接尾 讀音 文字列 順序로 決定하고 debug 로그에 남깁니다. 複數 候補
키에서는 選擇한 候補의 `preference`가 1, 나머지가 0입니다.

原本 標題語의 앞 하이픈이나 `senseinfo.pos`의 `의존 명사`가 接尾 用法의
根據입니다. 뒤 하이픈은 接頭辭로 處理합니다. 둘 以上의 漢字로만 된 키,
키와 讀音의 같은 音節 數, 共有 頭音法則 關係가 모두 맞아야 位置別 讀音을
짝짓고, 가능한 모든 짝과 寄與 識別子를 保存합니다. 같은 表記가 獨立語와
接尾 用法에 모두 나오면 獨立 候補도 남깁니다. 接尾 用法만 있는 讀音도 짝의
一部가 되더라도 獨立 候補로 保存하여 以前의 기본값을 維持합니다. 關係가
不明確한 讀音은 합치지 않습니다. 單一 漢字는 檢索 候補로 保存하되 짝짓지 않고
엔진의 位置別 頭音法則을 씁니다. 北韓語 讀音을 南韓 表記로 바꾸지 않습니다.

抽出 結果는 分類, 키, 讀音, 接尾 讀音 順이며 原本 順序에 依存하지
않습니다. `--check`는 네 出力을 모두 抽出/檢證한 뒤 比較하고, 差異를 모두
報告하며 파일을 만들거나 덮어쓰지 않습니다. 一般 抽出도 네 分類의 檢證을
끝낸 뒤에만 出力 파일을 엽니다.

分類의 優先順位는 그대로입니다. `ChainDictionary`에서 앞 辭典이 키의
候補 集合 전체를 代替하므로 北韓語를 먼저 놓아도 一般語 候補가 섞이지
않습니다. 選擇되지 않은 讀音은 同音異義語 註釋을 만들지 않습니다.


實行 時 使用法
--------------

Rust crate는 分類別 讀入 函數를 提供합니다:

 -  `gukhanmun_opendict::general()`
 -  `gukhanmun_opendict::north_korean()`
 -  `gukhanmun_opendict::dialect()`
 -  `gukhanmun_opendict::archaic()`

Rust와 CLI에서 `Preset::KoKp`는 北韓語 辭典을 기본으로 포함합니다.
JavaScript 바인딩은 어느 프리셋에서도 辭典 데이터를 自動으로 불러오지
않습니다. 必要한 分類를 `@gukhanmun/opendict-fst`나
`@gukhanmun/opendict-cdb`에서 불러와 `load({ dictionaries: [...] })`에
넘기면 됩니다.
